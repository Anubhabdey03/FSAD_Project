Abstract

What is eBaazee.com?

eBaazee.com is a web-based online auction platform enabling registered users to buy and sell products through a competitive bidding mechanism. Sellers list products with a minimum bid, maximum bid, and auction duration. Buyers place a single sealed bid per product within the allowed range.

Built on a three-tier architecture — React 18 SPA → Spring Boot REST API → PostgreSQL. Authentication is stateless via JWT. Real-time bid statistics are delivered via WebSocket (STOMP/SockJS). Three roles — BUYER, SELLER, ADMIN — each have dedicated dashboards covering the full auction lifecycle: listing → bidding → freeze → purchase.

Problem Statement

Why eBaazee?

❌ Traditional E-Commerce Problems

  • Fixed prices — no market-driven price discovery
  • Sellers undervalue rare or unique items
  • No competitive incentive for buyers
  • No transparent bidding history or fairness

✅ eBaazee Solution

  • Time-bounded competitive auctions
  • Sellers get market-driven prices
  • Buyers compete transparently with live stats
  • Admin controls lifecycle — freeze and close
  • Real-time WebSocket bid stats for all viewers

Features

Key Features & Special Features

🔐

Role-Based Access

BUYER, SELLER, ADMIN — dedicated dashboards and protected routes. JWT tokens carry role claims, enforced by Spring Security @PreAuthorize.

⚡

Live Bid Stats ★ Special

WebSocket (STOMP over SockJS) pushes count, highest, lowest, average to every viewer on every new bid — no page refresh.

⏱️

Auction Countdown ★ Special

end_time stored server-side. Frontend renders a live second-by-second countdown. Backend enforces independently.

🧊

Admin Freeze

Admin stops any ACTIVE auction (→ FROZEN). Only the highest bidder sees the "Purchase Now" button.

📧

Email Notification ★ Special

JavaMailSender sends win notification on purchase. Non-blocking — email failure never fails the purchase transaction.

📊

Auction Reports

Admin and owning Seller generate full reports: all bids, bidder names, amounts, highest / lowest / average stats.

DB Design — DDL

DDL — Schema Definition

-- users table
CREATE TABLE users (
  user_id     BIGSERIAL PRIMARY KEY,
  name       VARCHAR(100) NOT NULL,
  email      VARCHAR(150) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  role       VARCHAR(10) CHECK (role IN
    ('BUYER','SELLER','ADMIN')),
  created_at TIMESTAMP DEFAULT NOW()
);

-- product table
CREATE TABLE product (
  product_id  BIGSERIAL PRIMARY KEY,
  title      VARCHAR(200) NOT NULL,
  min_bid    DECIMAL(12,2) NOT NULL,
  max_bid    DECIMAL(12,2) NOT NULL,
  start_time TIMESTAMP NOT NULL,
  end_time   TIMESTAMP NOT NULL,
  status     VARCHAR(10) DEFAULT 'ACTIVE',
  seller_id  BIGINT REFERENCES users,
  category_id BIGINT REFERENCES category
);
-- bid (1 bid per user per product)
CREATE TABLE bid (
  bid_id     BIGSERIAL PRIMARY KEY,
  amount     DECIMAL(12,2) NOT NULL,
  bid_time   TIMESTAMP DEFAULT NOW(),
  user_id    BIGINT REFERENCES users,
  product_id BIGINT REFERENCES product,
  UNIQUE (user_id, product_id)
);

-- purchase (1 winner per auction)
CREATE TABLE purchase (
  purchase_id  BIGSERIAL PRIMARY KEY,
  purchase_time TIMESTAMP DEFAULT NOW(),
  amount_paid  DECIMAL(12,2) NOT NULL,
  user_id      BIGINT REFERENCES users,
  product_id   BIGINT UNIQUE REFERENCES product
);

Special Features — Deep Dive

Special Features — Deep Dive

⚡ WebSocket Real-Time Bid Stats

1️⃣Buyer places bid via POST /api/products/{id}/bid
2️⃣BidService saves bid → calls SimpMessagingTemplate.convertAndSend("/topic/products/{id}", stats)
3️⃣All viewers subscribed via SockJS→STOMP receive updated {count, highest, lowest, average}
4️⃣BidStatsPanel React component re-renders — zero page refresh

⏱ Server-Enforced Auction Timer

Frontend CountdownTimer ticks every second from end_time. Backend independently validates now() < product.endTime on every bid — client timer is display only; server is the authority.

🛡 Bid Validation Chain (ordered)

①Product exists?→ 404
②Buyer ≠ Seller of product?→ 403
③Status ACTIVE + not past end_time?→ 400
④Amount within [minBid, maxBid]?→ 400
⑤User not already bid on this product?→ 409
⑥Save bid + broadcast stats→ 200
