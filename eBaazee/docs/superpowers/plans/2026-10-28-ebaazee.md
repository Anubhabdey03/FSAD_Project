# eBaazee.com Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a full-stack online auction platform (eBaazee.com) with buyer, seller, and admin roles, JWT auth, real-time bid stats via WebSocket, and a React SPA frontend.

**Architecture:** Spring Boot 3.x REST API + MySQL backend; React 18 + Vite SPA frontend; Spring Security with JWT for stateless auth; WebSocket (STOMP/SockJS) for real-time bid updates.

**Tech Stack:** Java 17, Spring Boot 3.x, Spring Data JPA, Hibernate, MySQL 8.x, jjwt, JavaMailSender, React 18, Vite, React Router v6, Axios, SockJS + STOMP client.

**Spec:** `docs/superpowers/specs/2026-10-28-ebaazee-design.md`

---

## Global Constraints

- Java 17+; Spring Boot 3.x; MySQL 8.x
- All monetary values: `DECIMAL(12,2)`
- Passwords: BCrypt strength 12; never logged or returned in responses
- JWT: HS256, 24-hour expiry; role claim key: `role`
- One bid per (user_id, product_id) enforced at DB level (UNIQUE constraint) AND service level
- Bid amount must satisfy: `product.min_bid ≤ amount ≤ product.max_bid`
- Bidding rejected if `product.status != ACTIVE` or `now > product.end_time`
- A user cannot bid on their own product
- API base path: `/api`
- React dev server: `http://localhost:5173`; Spring Boot: `http://localhost:8080`
- CORS: allow `http://localhost:5173` in development

---

## Review Focus

- **Duplicate bid attempt:** Buyer submits a second bid on the same product — must return 409 Conflict, not 500 from DB constraint violation. Test in Task 5.
- **Bid on frozen/closed auction:** Bid POST after admin freeze — must return 400 with clear message. Test in Task 5.
- **Bid on own product:** Seller tries to bid on their own listing — must return 403. Test in Task 5.
- **Highest-bidder purchase enforcement:** A non-winning buyer calls `/purchase` — must return 403. Test in Task 6.
- **End-time expiry vs admin freeze:** Auction past `end_time` but not yet frozen — bid must still be rejected (server checks `end_time`). Test in Task 5.

- Create: `src/api/seller.js`, `src/api/admin.js`, `src/api/reports.js`
- Create: `src/pages/SellerDashboardPage.jsx`, `src/pages/NewProductPage.jsx`
- Create: `src/pages/AdminDashboardPage.jsx`, `src/pages/AdminReportPage.jsx`
- Create: `src/pages/BuyerBidsPage.jsx`, `src/pages/BuyerPurchasesPage.jsx`

**Interfaces:**
- Consumes: seller, admin, report, buyer endpoints from Tasks 4, 6
- Produces: all role-specific dashboards functional

- [ ] **Step 1: Implement `NewProductPage.jsx`**

  Form: title, description, imageUrl, category (dropdown from `/api/products` category list), minBid, maxBid, durationHours. Submit → `POST /api/seller/products` → redirect to seller dashboard.

- [ ] **Step 2: Implement `SellerDashboardPage.jsx`**

  Fetch `GET /api/seller/products`. Table: title, status, bid count, highest bid, end time. Link to report for each.

- [ ] **Step 3: Implement `AdminDashboardPage.jsx`**

  Fetch `GET /api/admin/products`. Table with Freeze button per ACTIVE product → `PUT /api/admin/products/{id}/freeze` → refresh. Tab or section for user list from `GET /api/admin/users`.

- [ ] **Step 4: Implement `AdminReportPage.jsx`**

  Fetch `GET /api/reports/products/{id}`. Display product info + table of all bids (bidder name, amount, time) + summary stats (count, avg, highest, lowest).

- [ ] **Step 5: Implement `BuyerBidsPage.jsx` and `BuyerPurchasesPage.jsx`**

  `BuyerBidsPage`: fetch `GET /api/buyer/bids` → table of product title, bid amount, bid time, status.  
  `BuyerPurchasesPage`: fetch `GET /api/buyer/purchases` → table of product title, amount paid, purchase time.

- [ ] **Step 6: Verify manually (full flow)**

  1. Register as SELLER → list a product (5-minute auction).
  2. Register as BUYER → browse → find product → place bid → see live stats update.
  3. Admin login → freeze auction → highest bidder can see Purchase button.
  4. Buyer purchases → product shows CLOSED.
  5. Seller sees outcome in dashboard. Admin sees report.

- [ ] **Step 7: Commit**

  ```bash
  git commit -m "feat: seller, admin, buyer dashboards and report page"
  ```
